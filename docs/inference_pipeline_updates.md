## 🔍 2. 상세 변경 사항 및 로직 분석

### 2.1. Long-Context 지원 극대화 (128K 토큰 확장)
- **기존 문제점**: `SEQ_LEN = 2048`, `max_position_embeddings = 2048` 설정으로 인해, 몇 마디 분량의 과거 문맥만 주입되어 곡 후반부 편곡 시 전반부의 테마나 악기 구성 정보를 소실했습니다.
- **개선 로직**:
  ```python
  # Qwen2.5-0.5B의 최대 스펙인 128K 전체 활성화
  config.max_position_embeddings = 128000
  ...
  SEQ_LEN  = 128000
  MAX_CTX  = SEQ_LEN - 8192
  ```
- **효과**: 프롬프트 길이가 수만 토큰에 달하는 대곡이나 복잡한 오케스트레이션 곡에서도 과거 마디 정보를 안정적으로 담아내어 일관성 있는 편곡 품질을 유지합니다.

### 2.2. 무결점 마디 매핑 및 변박자 완벽 대응
- **기존 문제점**: 곡의 박자표(`time_signature`) 변화를 고려하지 않고 단순히 곡 시작 시점의 박자수(예: 4/4박자의 4)로 전체 틱을 나누어 마디(`bar_idx`)를 산출했습니다. 이로 인해 4/4박자에서 3/4박자로 바뀌는 등 변박이 발생하면 마디 경계가 무너지고 토큰 시간대 정렬이 어긋났습니다.
- **개선 로직**:
  ```python
  # ── 변박 완벽 대응을 위한 마디별 누적 시작 틱 사전 계산 ──
  bar_start_ticks = [0]
  acc = 0
  while acc < end_tick or len(bar_start_ticks) < 10:
      bt = pm.tick_to_time(acc)
      ts_idx = max(0, bisect.bisect_right(ts_times, bt) - 1)
      bpb = ts_changes[ts_idx].numerator if ts_idx < len(ts_changes) else 4
      acc += res * bpb
      bar_start_ticks.append(acc)

  # ── 이진 탐색 기반 무결점 마디 매핑 ──
  note_tick = pm.time_to_tick(n.start)
  bar_idx = max(0, bisect.bisect_right(bar_start_ticks, note_tick) - 1)
  ```
- **효과**: 마디 단위 슬라이딩 윈도우의 구조적 정합성을 100% 보장하며, 복합 박자 및 잦은 변박 곡에서도 정확한 마디 시작 토큰(`BAR_START`)과 정규화된 상대 시간 토큰(`TIME=`)을 부여합니다.

### 2.3. 편곡의 예술성 보존 (도약 완화 제거)
- **기존 문제점**: `postprocess()` 내부에서 단선율 악기 생성 시 이전 노트와의 피치 간격이 12반음(1옥타브)을 넘어가면 강제로 옥타브를 낮추거나 높이는 평탄화(Smoothing) 코드가 동작했습니다.
- **개선 로직**: 후처리의 `6. 단선율 악기만: 큰 도약 완화` 섹션을 전체 주석 처리하여 비활성화했습니다.
- **효과**: 피아노, 플루트, 바이올린 등에서 의도적으로 연출된 도약 진행이나 글리산도적 고음 도약 멜로디가 인위적으로 뭉개지는 현상을 방지하고, AI 모델이 생성한 원본 선율의 다이내믹을 보존합니다.

### 2.4. 윈도우 시작 시 토큰 추가 주입 
- **기존 문제점**: 윈도우 시작 시 `BAR_START`와 `INST`만 강제 주입하여, 모델이 해당 마디의 전반적인 분위기(조성, 박자 등)를 인지하지 못한 채 첫 음을 뱉는 경향이 있었습니다.
- **개선 로직**: `generate_sliding_window` 함수 내에서 현재 마디의 `bar_tokens`로부터 `KEY_`, `METER_`, `DENSITY_` 토큰을 추출하여 강제 주입(Forced Injection) 목록에 포함시켰습니다.
- **효과**: 모델이 마디의 배경 정보(조성, 박자, 밀도)를 명확히 인지한 상태에서 타겟 악기의 첫 음을 생성하여 화성적 정합성을 향상시켰습니다.

### 2.5. 결정론적 생성 탈피 (고정 시드 해제 및 무작위성 확보)
- **기존 문제점**: 난수 시드(`seed`)가 `42`로 고정되어 있어, 동일한 곡에 대해 매번 **1bit의 오차도 없는 동일한 결과**만 출력되었습니다. 이는 AI 서비스의 핵심인 '다양성'과 '사용자 선택권'을 제한하는 요소였습니다.
- **비유로 이해하기 (다트 던지기)**:
    - **동적 시드 (Random Seed)**: 다트를 던질 때마다 미세한 바람, 손동작의 차이(난수)에 의해 궤적이 달라집니다. 어떤 때는 정중앙 '10점'을 맞히고, 어떤 때는 살짝 비껴나가며 **매번 새로운 결과**를 만들어냅니다.
    - **고정 시드 (Seed 42)**: 파이토치 엔진이 "첫 번째 다트는 무조건 왼쪽으로 15도, 힘 1.5로 던져라"라고 **궤적을 미리 고정**해버린 상태입니다. 백 번을 던져도 다트는 항상 똑같은 구멍에만 꽂히게 되며, 변주가 불가능한 '오르골'과 같은 상태가 됩니다.
- **개선 로직**:
  ```python
  # 매 실행 시마다 새로운 난수 스트림 생성
  seed = random.randint(0, 2147483647)
  torch.manual_seed(seed)
  ```
- **효과**: 원곡의 화성적 틀은 유지하면서도, 실행할 때마다 미세하게 다른 선율이 가능해져 사용자에게 다채로운 편곡 옵션을 제공합니다.
